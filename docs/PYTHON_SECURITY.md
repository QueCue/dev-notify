# 安全边界

当前为未发布的 alpha 源码工程，不应宣称已完成安全审计或真实双平台验收。

## 数据与权限

- `send` 会将用户指定的正文、标题、辅助信息发送至所选第三方通知平台。
- 配置文件不接受明文密钥字段；支持环境变量与系统凭据引用。环境变量显式存在时优先，空值也覆盖。环境变量不是保险库，仍可能被同用户进程读取或被子进程继承。
- Windows 使用当前用户 DPAPI，磁盘仅写加密 blob；macOS 使用 Keychain 原生 API，不把秘密放到子进程参数。两者都不能防御已被控制的同用户进程；使用时秘密会进入 Python 进程内存，不保证全部内存副本被安全擦除。
- 配置向导使用隐藏输入，不允许 getpass 静默回退到回显。保存前需最终确认，不联网验证，不自动发送测试通知。
- 原生 Keychain 读取默认禁止交互，授权或解锁失败即报错；向导允许系统授权提示。真实 macOS 权限流程仍待验收。
- 不自动读取项目文件、应用会话、Git/SVN 元信息，不修改任何应用 hooks。
- 不启动回复桥接、不开放监听端口、不执行远程输入。
- HTTPS 不跟随重定向，避免向其他地址转发凭据；不关闭 TLS 验证。
- 默认日志不打印 URL、凭据、通知正文或服务端原始响应。
- 模板仅排他创建、不覆盖旧文件。向导编辑需确认；新凭据写入校验成功后才切换配置，成功后移除旧条目。配置副本若共享旧引用，也需同步更新。
- 配置与系统存储不是跨系统原子事务。失败会尝试清理本次新条目；进程被强杀或断电时可能留有孤立条目/锁，不自动清理未知数据。凭据清理失败只输出非敏感引用 ID。
- POSIX 文件使用用户权限；Windows 权限继承仍需要真实安装验收，不能把 chmod 等同于 Windows ACL 保护。DPAPI 密文、凭据引用和接收人配置同样不应公开。

## 公开前检查

仅迁入白名单源码。不得发布真实配置、环境文件、密钥、日志、会话映射、缓存和构建临时产物。扫描完整发布目录以及 Git 历史，核对代码权属和第三方许可。密钥若曾公开应立即撤销轮换，删除文件不能撤销泄漏。

安装器、自动更新、原生凭据存储、应用集成和远程输入会引入新的权限边界，必须独立评审和真实平台验证。

## 漏洞报告

当前没有公开仓库和安全联络渠道。正式发布前，维护者必须配置私密漏洞报告方式。不要在公开 issue 中贴出真实 Token、webhook 或包含项目内容的完整日志。
